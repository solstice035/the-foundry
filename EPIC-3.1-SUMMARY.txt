================================================================================
MANUAL TESTING WORKFLOW
================================================================================

PER POST (25-30 min):
1. Choose build/topic from pipeline output
2. Select content type from templates
3. Draft using voice-guide.md
4. Self-review against checklist
5. Post on X (primary) + Reddit (if strong)
6. Log in engagement-tracking.md
7. Respond to comments (Reddit 2-hour rule)
8. Update metrics at 24h and 7d
9. Document learnings in patterns.md

WEEKLY REVIEW (30 min):
1. Calculate averages by type/platform/timing
2. Identify top performer and why
3. Identify underperformer and why
4. Validate patterns (hypothesis → confirmed)
5. Update voice-guide.md with learned language
6. Adjust templates if needed

COMPLETION (after 2-3 weeks):
- 4-6 posts published
- Each content type tested ≥1x
- 3+ high-confidence patterns identified
- 3+ anti-patterns documented
- Voice guide refined with real examples
- >60% would be "approved as-is" in hindsight

================================================================================
CONTENT TYPES & EXAMPLES
================================================================================

1. BUILD ANNOUNCEMENT (successful build)
   "Saw devs complaining about X. Built a thing while I slept."

2. PROCESS THREAD (weekly meta)
   "I built a system that watches dev Twitter overnight and builds apps..."

3. REJECTION POST (no builds)
   "My AI pipeline analyzed 14 trends last night. Built zero. Here's why."

4. TREND FORECAST (emerging pain point)
   "Pain point I'm tracking: API key management across providers."

5. CONSENSUS TAKE (multi-perspective)
   "Ran 5-perspective analysis: User, Critic, Builder, Marketer, Investor."

6. FAILURE POST (build failed)
   "Hit WebSocket wall at 60%. Lesson: scope to single-user first."
